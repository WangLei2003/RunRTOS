# 实现规范

## 运行时边界

- 固件不得依赖 libc、CMSIS、厂商 HAL、CMSIS-RTOS 或第三方运行时源码。
- `include/runrtos`、`src/core`、`src/runtime`、`src/kernel` 和通用驱动禁止包含
  `stdint.h`、`stddef.h`、`stdbool.h`、`string.h`、`stdlib.h`、`stdio.h` 等标准头。
- 允许显式链接经过封装的 GCC 算术辅助运行时；映射文件中的每个此类符号必须可解释。
- 编译器内建、预定义类型和属性只能通过 `core/run_compiler.h` 引入。
- 汇编适配只能出现在 `arch` 的架构实现目录中，不得散落到内核或应用代码。

## 内存和上下文

- 内存系统必须在内核及上层对象创建前初始化。
- 上层线程、同步对象、定时器、设备和线程栈必须通过 RunRTOS 内存系统动态创建。
- 分配、释放和对象构造禁止在 ISR 中调用。
- 中断与任务共享的数据必须进入临界区，或使用明确的 `*_from_isr` API。
- 所有超时比较必须使用有符号差值处理 tick 回绕。
- 阻塞调用返回前必须重新检查资源状态，不能假定被唤醒就等于资源已获得。

## 断言和错误

- 外部输入错误返回 `RunStatus`，不得依赖断言代替参数检查。
- 内部不变量使用 `RUN_INVARIANT`；用户误用使用分级断言或明确状态码。
- 禁止静默吞掉错误；可忽略的返回值必须显式转换为 `RUN_VOID`。
- 断言和故障路径必须保留可诊断信息，并允许板级注册输出钩子。

## 评审门槛

- 新增依赖必须与 CMake 目标方向和公共包含路径一致。
- 新增公共符号必须符合命名表并考虑 ABI 与裁剪影响。
- 新增平台不得修改内核公开接口才能编译。
- 新增可选模块必须验证 full、release 和 minimal 构建矩阵。
- 评审必须确认没有标准头、厂商头、私有结构泄漏和未说明的编译器扩展。
